# 本机可视化 Demo

默认使用模拟账号、模拟知识、Mock 生成和 TF-IDF 检索，不需要外部模型密钥。真实服务配置与真实质量验收分开显示。

## 启动和新建演示数据

在项目根目录执行：

```powershell
pwsh -File scripts/run-demo.ps1
```

打开 `http://127.0.0.1:5180`。本机解释器使用已恢复的 `backend/.venv`。数据位于 `logs/demo/default`，与 `.env` 中的业务数据库分离。演示实例使用独立、稳定的签名密钥，日志也独立保存。

重新开始演示：

```powershell
pwsh -File scripts/run-demo.ps1 -Fresh
```

这会创建新的空演示实例，保留旧实例，避免删除现有数据。可以用 `-Instance` 返回之前的实例，实例目录须包含匹配的演示所有权标记。

自动功能验收并退出：

```powershell
pwsh -File scripts/run-demo.ps1 -Fresh -Check -DemoCheck
```

模拟模型不可达的降级验收：

```powershell
pwsh -File scripts/run-demo.ps1 -Fresh -SimulateModelFailure -Check -DemoCheck
```

故障实例只向本机不可达的模拟端点发请求，使用虚构的测试密钥；应看到 `offline-fallback` 回答和正常的事件记录。它证明降级行为，不证明真实 LLM 服务可用。

## 五分钟演示流程

1. 使用 Employee 演示账号登录。选择“安全知识”卡片，点击 Send，展开 KB-001 来源核对中文政策。
2. 创建新对话，选择“钓鱼报告”。观察 Medium 风险和已创建工单，界面会继续询问是否输入密码或验证码。
3. 同一对话选择“补充事实”。观察 High 风险与同一个工单编号，展示“已提交但尚未确认人工接手”的状态。
4. 退出 Employee，登录 Security Team。打开 Tickets，选中该工单，核对补充事实、风险变化和时间线；点击 Move to in progress，添加模拟处理备注，完成解决流程。
5. 打开 Dashboard，检查实际风险分布、事件数量和未响应数量。看板和队列在可见时每 15 秒更新。
6. 新对话展示可疑附件、VPN 指南及员工/安全团队相同问题的来源权限差异。权限由后端实际身份决定。

流程面板来自实际响应：意图、当前角色范围、使用来源、回答依据、当前/峰值风险和工单状态。示例卡片只填入输入框，不自动提交事件。时间线使用带时区的 UTC 数据，由浏览器转换为本地时间。

桌面与窄屏均可使用；审计表格在其自身容器内横向滚动，页面不应出现横向溢出。浏览器刷新后需要重新登录，因为访问令牌只保存在前端内存；业务会话与工单仍保存在当前演示实例中。

实际验收记录见 [PHASE_PROGRESS.md](PHASE_PROGRESS.md)。Docker 浏览器验收和真实模型验收仍需各自的运行证据。

Phase 8 的 [当前交接](PHASE8_HANDOFF.md) 和 [13项验收矩阵](ACCEPTANCE_MATRIX.md) 记录具体制品/证据与未完成门禁。现有桌面/窄屏截图对应当前未改的前端；离线演示数据与 `.env` 业务数据分离，不能在对外演示时称为真实模型或正式生产部署。

Security 的 Tickets 页现有“通知送达”面板，可查看实际队列、刷新、分页、重排和打开原工单。未配置接收端时显示等待，接收端确认与人工接手分别展示；通知链接 `/?ticket=<编号>` 在登录后打开工单，仍受后端权限控制。正式接收端协议见 [OPS_NOTIFICATIONS.md](OPS_NOTIFICATIONS.md)。

`run-demo.ps1` 明确清空通知端点、签名/CA 配置并禁用通知 worker；因此即使本机后来配置正式收件渠道，演示数据也不会向其发送。测试及模型/质量评测同样隔离通知；真实模型评测仅保留所选模型服务配置。需要演示实际通知时使用隔离的测试接收端和专用运维演练入口。
