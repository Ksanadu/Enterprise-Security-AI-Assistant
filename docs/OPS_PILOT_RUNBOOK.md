# 单机试点部署与故障处置手册（待部署验收）

适用于单机 SQLite 的受控试点。实际生产 TLS、Docker、正式接收/告警、业务保留策略和发布回滚尚未验收；本手册是执行准备，不是上线证明。

## 上线条件与责任

| 责任 | 上线前必须提供 |
| --- | --- |
| 应用维护者 | 冻结代码/构建摘要、迁移版本、检查记录、对应上一可用构建 |
| 平台维护者 | HTTPS 入口、受限 API/数据目录、稳定服务运行身份、进程监督及就绪探测 |
| 安全值班负责人 | 正式接收端/负责人渠道、接收端持久化去重及签名、告警调度和响应制度 |
| 数据负责人 | 经批准的聊天/工单/审计/备份保留期限、保全规则、授权删除范围及恢复目标 |
| 验收审阅者 | 真实模型答案支持审阅、新独立质量集及结果；不得由调优数据替代 |

具体人名和服务账户由试点方填写，本仓库没有把演示账号作为正式负责人。[正式账号配置工具](OPS_ACCOUNTS.md) 可先预览、备份并创建显式角色账号；账号转换工具只停用演示账号。正式职责、审批及企业身份接入仍须部署方确定。

## 部署顺序

1. 验证正式收件渠道、模型/预算和系统外部条件。秘密从权限受限配置或秘密管理提供，不能打印 `.env`、复制到命令参数或报告。身份签名秘密跨 worker/重启保持稳定；备份数据库不包含外部秘密管理的恢复副本。
2. 取得经批准的维护窗口，暂停写入并确认没有正在进行的迁移。对当前数据库执行 [在线备份](OPS_BACKUP.md)，保存完整性检查、摘要清单和迁移版本。首次部署同样使用独立正式目录，避免复用演示实例。
3. 在隔离副本先执行 `alembic upgrade head`，验证迁移、就绪、鉴权/权限、原设计场景和待处理任务。确认正式账号可用，再按 [转换工具](OPS_NOTIFICATIONS.md) 停用已知演示账号。不要直接删除用户行。
4. 对维护中的数据库执行一次迁移，完成后启动应用 worker。生产配置拒绝演示开关、已知活跃演示账号、默认秘密、不安全通知、关闭共享预算/恢复/维护。SQLite 数据目录应仅授权服务身份；恢复和备份目录也包含受限业务数据。
5. 由 TLS 入口访问 SPA/API，验证代理、CSP、证书链和续期方案；只信任实际受控代理。后端管理端口不直接公开。Docker 卷写权限和容器健康状态须通过实际运行验收。
6. 执行角色/模式矩阵、模拟 High/Critical 事件、签名接收和超时负责人提醒；由值班人员实际接手并核对时间线。运行外部巡检并验证“故障触发 → 正式接收 → 恢复消除”，同时验证监督器能发现巡检本身停止。
7. 保存具体构建、数据库版本、脱敏配置清单、执行记录、操作时间及值班责任，恢复写入。任何必须项缺少证据则保持“未验收”。

## 发布回滚操作准备

不能在有业务/预算/通知行的库上通过删表 downgrade 回退。本轮迁移会拒绝此操作；空库回退测试不代表发布回滚。

正式演练要使用当前和上一可用的**两个不可变构建**，以及升级前已校验的独立备份。先隔离写入，登记冻结时刻和已提交任务，再部署候选构建；故意触发已约定的就绪/启动失败后，停止候选实例，将备份恢复到新数据库文件，启动上一可用构建，重查账号/会话、权限、知识库、工单/编号、未完成任务和外部通知去重账本。恢复文件不得覆盖正在使用的数据库，应用必须明确切换到选定文件。

回滚数据库可能丢失备份后新写入；因此必须在演练中冻结写入并登记实际损失范围。若上一构建可安全读取新 schema，优先仅切换应用构建、保留数据；兼容性必须先在隔离副本证明。不能假定每个旧版本都兼容。外部通知不会随数据库回退，接收端须按同一事件 ID 去重，并核查已发送/结果不确定的事件。

2026-10-13 已用两个本地校验制品完成实际独立进程 A→B 故障→快照恢复→A 演练，包含会话/RBAC、唯一待处理工单及 TLS 接收端重放去重，参见 [OPS_RELEASE.md](OPS_RELEASE.md)。这是本地模拟部署证据，正式镜像/进程监督/入口 TLS 与秘密托管仍未验收。

## 故障处置

| 信号 | 首要操作 | 恢复确认 |
| --- | --- | --- |
| 就绪 503 / 知识库不可用 | 查文件/索引/存储权限及配置；保持存活和鉴权可用 | ready 200，角色检索符合权限；不能只看进程存在 |
| 模型失败/预算耗尽 | 查供应商、配置及请求预算，保留安全规则/离线降级 | 新真实调用通过，调用/耗时有记录，高风险任务仍送达 |
| 升级任务积压 | 恢复数据库可写及恢复 worker | pending 任务完成且只产生一个对应工单 |
| 通知积压/耗尽 | 核查 TLS、签名、确认头和接收端去重账本，再授权重排 | 接收端确认与数据库 delivered 对应；未伪造人工接手 |
| 人工响应超期 | 值班负责人打开实际工单处理 | IT/Security 非自动时间线记录消除当前升级超期 |
| 共享预算存储故障 | 恢复共享 SQLite/权限，不切回进程内预算 | ready 200，多 worker 预算与锁定连续 |
| 登录失败/演示账号启动拒绝 | 核查正式身份/配置，按转换流程处理 | 正式账号登录和 RBAC 成功，已停用账号会话失效 |

## 数据保留和恢复范围

已实际定时清理过期共享预算及过期认证会话。2026-10-13 新增 [业务保留与保全](OPS_RETENTION.md)，具有实际后台入口、校验备份、失败回滚、保全排除及专用备份过期。当前未配置任何真实组织的批准政策，现有业务数据未清理。

数据负责人需确定各类期限、调查保全、外部备份副本与通知接收端去重账本保留及授权审批。模拟数据批次、恢复和保全已验证，真实期限和批准责任不能由测试政策代替。字段擦除也不能视为磁盘不可恢复；加密、WAL/文件系统残留及旧备份恢复后的再次清理需另行验收。

实际备份演练验证已提交 WAL、版本/表、待处理任务和编号；生产配置 API 恢复验证会话/RBAC及恢复 worker，并向本机 TLS 接收端送达。磁盘/备份加密、ACL、密钥托管、跨主机恢复、备份调度及实际 RPO/RTO仍需试点方执行和记录。
